We study criterion-level clinical-trial eligibility screening: given a patient note, a criterion type (inclusion or exclusion) and a criterion text, a model must return one of the expert label categories, including ``not enough information'' and ``not applicable'', together with supporting sentence IDs. We use the NCBI TrialGPT criterion annotations (1{,}015 annotations, 53 patients, patient-grouped 37/8/8 split, seed 42). A Qwen2.5-1.5B-Instruct model with a LoRA adapter, trained in a disclosed joint session on a shared GPU, is evaluated by us on a CPU laptop before and after adaptation. Beyond accuracy, we implement our own pre-allocated KV-cache decoder, a tiled online-softmax attention, and a greedy speculative decoder with a Qwen2.5-0.5B-Instruct draft, and wrap everything in a browser application. On the 206 held-out test criteria (8 patients), the adapted model reaches 0.733 accuracy and 0.528 macro-F1 (95\% CI 0.456--0.594), against 0.160 and 0.129 for the unadapted base model under identical prompts and greedy decoding (129 criteria corrected, 11 broken). It returns valid structured output for every criterion and an evidence micro-F1 of 0.58. Error analysis exposes a systematic failure: exclusion criteria lacking evidence are labelled ``not excluded'' rather than ``not enough information''. Our cached decoder is token-identical to the uncached reference and 7--27$\times$ faster in decoding. Tiled attention matches a float64 reference to $2.5\times10^{-6}$ in fp32 and needs about 60$\times$ less extra memory at 4{,}096 tokens, but runs slower than PyTorch's fused kernel on the CPU. Speculative decoding is lossless with 73--93\% draft acceptance, yet brings no end-to-end speed-up for short CPU outputs. We explain this from measured draft and verification costs.
